01Contexte & objectifs

Dans un établissement, le parc informatique (postes, serveurs, équipements réseau) est difficile à suivre manuellement. GPI centralise tout dans une seule console.

  • ✓
    Inventorier — recenser les équipements et leur état.
  • ✓
    Superviser — relever les métriques (CPU, RAM, disque) en temps réel.
  • ✓
    Alerter — détecter automatiquement les anomalies.
  • ✓
    Anticiper — prédire les pannes avant qu'elles n'arrivent.

03Architecture — deux applications

Frontend · navigateur

React + Vite

L'interface (la « console »). Communique avec le serveur uniquement via des appels HTTP / JSON.

Backend · serveur

Laravel + PostgreSQL

L'API REST et la logique métier. Détient les données, applique les règles et la sécurité.

Navigateur  ⇄  API REST (JSON, jeton Sanctum)  ⇄  Base PostgreSQL

Deux applications indépendantes, hébergeables sur des serveurs distincts. Aucun code partagé — meilleure sécurité et maintenance.

07Sécurité & bonnes pratiques

  • ✓
    Contrôle d'accès par rôle — chaque action vérifiée côté serveur (Admin / Technicien / Employé).
  • ✓
    Jetons Sanctum — authentification sans mot de passe stocké côté client.
  • ✓
    CORS verrouillé — seul le frontend autorisé peut appeler l'API.
  • ✓
    Secrets en variables d'environnement — jamais dans le code.
  • ✓
    Zéro valeur codée en dur — enums & configuration comme source unique.
  • ✓
    Architecture MVC + services — code organisé et testable.
  • ✓
    Validation des entrées — côté serveur, systématique.
  • ✓
    Interface bilingue — parité FR / EN vérifiée.
